# Herdr Prism development host profile

Run only after coordinating other CPU work. This tool creates disposable local files and processes; it never reads provider homes, writes user configuration, changes an existing checkout, or signals user processes. It requires a local C compiler, Python 3 with its standard `pty` module, Git, a fresh `dist/` build, and actual OS resource access. The C fixture is development support only: releases never compile code at runtime.

```sh
node scripts/build.mjs
node scripts/profile-host.mjs --self-check --output artifacts/profile-self-check
node scripts/profile-host.mjs --run --seconds 20 --output artifacts/macos-performance
node scripts/profile-host.mjs --run --seconds 10 --cpu-prof --output artifacts/macos-cpu-profile
```

On macOS the default helper must pass the packaged artifact checksum and Mach-O architecture verifier. An explicit `--helper PATH` is a developer override. Linux uses the real TypeScript procfs backend. Windows performance requires a separate ConPTY profiler and remains pending; this tool fails on Windows instead of substituting pipes for a terminal.

The full fixture declares 50 controlled Pi sessions through an in-process RPC implementation. Each tiny C harness has nine sleeping children: 500 actual OS processes. The collector samples actual kernel counters and verifies all 500 owned identities, while only the selected session's ten processes and transcript body are presented as current. At least 100 MiB of valid generated transcript history exists on disk. Every transcript and Git checkout is disposable and contains only fixed fixture text.

The collector, provider adapters, native helper, GitCache, input decoder, screen renderer, and TerminalUi are production implementations. An actual Unix PTY receives frames and sends keys. The host event source is controlled RPC, not a live Herdr connection; event-to-frame measurements exclude Herdr socket/CLI/subscription latency. Active work injects two snapshot changes and selected transcript appends per second, with about three keyboard tab transitions per second. The ordinary one-second refresh remains enabled. The documented process cadence is two seconds by default, one second while the selected Processes view is expanded, and five seconds when the observed selection is inactive. Git uses five seconds for working selection and thirty seconds for idle selection. Keyboard transitions call the production Processes visibility API. This does not establish performance for arbitrary event rates, busy 500-process applications, different transcript distributions, or actual Herdr.

CPU is normalized to one logical core. The worker records actual Node user/system deltas, exact live native helper counter deltas, and waited Git subprocess CPU with `wait4`. The development Git wrapper forwards literal arguments, preserves the production lock/timeout/environment rules, and includes its own CPU in the conservative total. Initial transcript loading, fixture creation, compilation and the profiler coordinator are outside the steady idle/active windows; initialization time is reported separately. No host-wide CPU percentage is attributed to the plugin. Phase timings include endpoint drain/accounting work.

Memory reports the worker RSS before loading the collector, its peak observed RSS, and their nonnegative difference. The budget uses that increment plus twice the maximum waited Git child-and-wrapper RSS as a conservative upper bound for the production two-job concurrency limit. Native helper RSS is reported separately and excluded, as the design budget permits. This is not heap size or unique physical memory; shared RSS pages may be counted repeatedly. Samples occur every 100 ms and cannot prove an unobserved shorter allocation peak.

Terminal p95 uses the nearest-rank percentile of actual control/keyboard write to observed changed PTY frame times. Event markers come from the selected session's changed title in the ordinary persistent header. Keyboard markers are the actual bracketed active tab. At the active window's end, inputs stop and every outstanding frame acknowledgement drains within three seconds before teardown; active CPU and wall-time accounting continue through that drain. No late latency observation is discarded. Reports contain counts, aggregates, timing and resource units, never raw terminal captures, transcripts or environment variables. The script writes `worker.json`, `terminal.json`, and `report.json` to the explicit output directory. A missed frame, denied resource API, missing process, incomplete child accounting or incomplete teardown fails the run.

The report checks idle CPU below 1%, active CPU below 3%, incremental memory below 150 MiB, event p95 below 500 ms and keyboard p95 below 100 ms. A full-scale run exits nonzero if any budget fails. `--self-check` uses two sessions, six processes and one MiB history; it validates mechanics and never certifies capacity. All fixture roots receive stdin EOF and reap their exact children. PTY cancellation terminates only its isolated worker process group. Final cleanup verifies the announced fixture PIDs are gone before reporting success.

`--cpu-prof` additionally saves a V8 CPU profile as `collector.cpuprofile`. It includes initialization and both phases, source URLs and function names, without captured transcript bodies or environment values. CPU profiling adds overhead; use it to identify hotspots, and repeat acceptance measurements without that flag. `cpuProfilerEnabled` identifies the instrumented report.

`certifiesFullHerdrPerformance` remains false even when every controlled-boundary budget passes. Full live Herdr performance, Windows ConPTY measurements, platform/architecture repetitions, and a sustained soak remain separate gates.
